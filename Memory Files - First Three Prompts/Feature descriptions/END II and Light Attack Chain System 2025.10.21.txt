=== END II + LIGHT ATTACK CHAIN SYSTEM ===
Date: 2025-10-21
Status: ✅ COMPLETE
Complexity: Medium (New engine tracking system)

=== FEATURE DESCRIPTION ===

Perk: End II
Effect: +6% ability base damage and +12% base damage increase to the final attack in a melee light attack chain.
Category: Weapon Perk (Conditional Damage Modifier)

Two-Part Bonus:
1. **Ability Damage**: +6% damage to ALL abilities (anything that's not LA/HA)
2. **Chain Finisher**: +12% damage to the FINAL light attack in a chain

Chain Finisher Positions (weapon-specific):
- **Flail**: LA 2 (2nd light attack finishes the chain)
- **Sword**: LA 3 (3rd light attack finishes the chain)
- **Other weapons**: Not defined (default = 999, never finishes)

=== TECHNICAL IMPLEMENTATION ===

## 1. Light Attack Chain Tracking System (NEW)

This was a **NEW ENGINE FEATURE** added to support END II and future chain-dependent perks.

### State Tracking

The engine tracks light attack chains per combatant:

```javascript
// Initialized per combatant
source.lightAttackChain = {
    count: 0,       // Current position in chain (1, 2, 3...)
    weapon: null    // Which weapon started this chain
};
```

**Why track weapon?**: If player switches weapons mid-chain, the chain resets. Can't continue Flail chain with Sword LAs.

### Chain Finisher Configuration

**File**: `/src/simulation/engine.js` (lines ~358-361)

```javascript
const WEAPON_CHAIN_FINISHERS = {
    'Flail': 2,   // Flail chain finishes on 2nd LA
    'Sword': 3    // Sword chain finishes on 3rd LA
};
```

**Extensibility**: Add new weapons here as they're implemented. If weapon not in map, finisherPosition = 999 (never finishes).

### Chain Logic Flow

**File**: `/src/simulation/engine.js` (lines ~355-404)

#### On LIGHT_ATTACK:

1. **Check weapon consistency**:
   - Same weapon as last LA? → Increment count
   - Different weapon or first LA? → Reset to 1, store weapon

2. **Determine if chain finisher**:
   ```javascript
   const finisherPosition = WEAPON_CHAIN_FINISHERS[source.weaponType] || 999;
   event.isChainFinisher = (source.lightAttackChain.count === finisherPosition);
   event.chainPosition = source.lightAttackChain.count;
   ```

3. **Attach metadata to event**:
   - `event.isChainFinisher`: boolean (true if this LA finishes chain)
   - `event.chainPosition`: number (1, 2, 3... current position)

4. **Log chain state** (for debugging):
   ```javascript
   console.log('[ENGINE] ⚔️ Light attack chain:', {
       weapon: source.weaponType,
       chainPosition: event.chainPosition,
       finisherPosition: finisherPosition,
       isChainFinisher: event.isChainFinisher
   });
   ```

#### On Non-Breaking Actions:

**Passive periodic effects don't break chains**:

```javascript
const NON_BREAKING_ACTIONS = ['DOT_TICK', 'HOT_TICK'];
```

- DOT/HOT ticks happen during LA chains → preserve chain state
- But don't set `isChainFinisher` on these events (only on actual LAs)

#### On Active Actions (Abilities, HA, Block, etc.):

**Active actions break the chain**:

```javascript
if (!NON_BREAKING_ACTIONS.includes(event.action)) {
    source.lightAttackChain.count = 0;
    source.lightAttackChain.weapon = null;
    event.isChainFinisher = false;
    event.chainPosition = 0;
}
```

**Why**: Player used an ability or heavy attack → resets combo counter.

### Chain Examples

**Flail Chain (finishes at LA 2)**:
```
LA 1: chainPosition=1, isChainFinisher=false
LA 2: chainPosition=2, isChainFinisher=true  ← END II +12% damage!
LA 3: chainPosition=3, isChainFinisher=false (chain continues past finisher)
```

**Sword Chain (finishes at LA 3)**:
```
LA 1: chainPosition=1, isChainFinisher=false
LA 2: chainPosition=2, isChainFinisher=false
LA 3: chainPosition=3, isChainFinisher=true  ← END II +12% damage!
LA 4: chainPosition=4, isChainFinisher=false
```

**Chain Break Example**:
```
LA 1 (Sword): chainPosition=1
LA 2 (Sword): chainPosition=2
ABILITY: chainPosition=0 (chain broken)
LA 1 (Sword): chainPosition=1 (chain restarted)
```

**Weapon Switch Example**:
```
LA 1 (Sword): chainPosition=1
LA 2 (Sword): chainPosition=2
[Switch to Flail]
LA 1 (Flail): chainPosition=1 (chain reset, different weapon)
LA 2 (Flail): chainPosition=2, isChainFinisher=true (Flail finishes at 2)
```

## 2. END II Bunker Implementation

**File**: `/src/simulation/bunkers/generated/perk_end_ii.js`

### Handler Logic

```javascript
function handler({ event }) {
  // Check if this is an ability (not LA/HA)
  const isAbility = event.action !== 'LIGHT_ATTACK' && event.action !== 'HEAVY_ATTACK';
  
  // Determine damage boost
  let damageBoost = 0;
  
  if (isAbility) {
    // +6% to all abilities
    damageBoost = 0.06;
  } else if (event.action === 'LIGHT_ATTACK' && event.isChainFinisher) {
    // +12% to chain-finishing light attacks
    damageBoost = 0.12;
  }
  
  // Only return modifier if applicable
  if (damageBoost === 0) {
    return {};
  }
  
  return {
    modifyDamage: [
      {
        id: 'end_ii_damage_boost',
        category: 'MISC_DAMAGE',
        value: damageBoost,
        source: 'End II'
      }
    ]
  };
}
```

### Key Design Decisions

**1. Why check `event.action` instead of just `event.isChainFinisher`?**

`event.isChainFinisher` could be `false` for two reasons:
- It's not a LIGHT_ATTACK (ability, HA, DOT_TICK, etc.)
- It's a LIGHT_ATTACK but not the finisher (LA 1 of Sword chain)

We need to distinguish:
- Abilities → +6% damage
- Chain-finishing LAs → +12% damage
- Non-finishing LAs → 0% damage

**2. Why return empty object `{}` instead of `null`?**

Both work, but `{}` is more explicit: "This bunker ran, but had no modifiers to apply."

**3. Why use `MISC_DAMAGE` category?**

END II is a generic damage boost (not crit, not type-specific). `MISC_DAMAGE` is the additive multiplier category for general damage boosts.

### Bunker Type: MODIFIER_BUNKER

- **Stroke**: 1 (runs during damage calculation)
- **Type**: MODIFIER_BUNKER (passive, checked every event)
- **Returns**: `modifyDamage` array with conditional modifiers

=== ARCHITECTURAL IMPACT ===

## New Engine Capabilities

**1. Per-Combatant State Tracking**:
- `lightAttackChain` object persists across events
- Enables combo-dependent perks

**2. Event Metadata Enrichment**:
- `event.isChainFinisher`: boolean

**3. Weapon-Specific Configuration**:

## Future Extensibility

This system enables future perks like:
- "First attack in chain deals +X% damage" (check `chainPosition === 1`)
- "Chain attacks beyond 3 gain +X% damage" (check `chainPosition > 3`)
- "Chain finishers apply Rend" (check `isChainFinisher`)
- "Gain stacking buff for each consecutive LA" (track `chainPosition`)

## Design Pattern: Conditional Modifiers

END II demonstrates a clean pattern for multi-condition perks:

```javascript
// 1. Determine all conditions
const isAbility = ...;
const isChainFinisher = ...;

// 2. Calculate appropriate value
let value = 0;
if (condition1) value = X;
else if (condition2) value = Y;

// 3. Early return if no modifier
if (value === 0) return {};

// 4. Return single modifier with calculated value
return { modifyDamage: [{ ... value }] };
```

**Benefits**:
- Single modifier object (not two competing modifiers)
- Clear precedence (abilities checked before chain finishers)
- Performance (early return if not applicable)

=== COMMON PITFALLS ===

## Pitfall 1: Forgetting Weapon-Specific Chains

**Wrong**:
```javascript
// Assumes all weapons finish at LA 3
if (event.chainPosition === 3) { ... }
```

**Right**:
```javascript
// Check isChainFinisher (engine already handles weapon-specific logic)
if (event.isChainFinisher) { ... }
```

**Why**: Flail finishes at LA 2, Sword at LA 3. Use `isChainFinisher` to handle all weapons correctly.

## Pitfall 2: Multiple Competing Modifiers

**Wrong**:
```javascript
// Returns TWO modifiers (only one applies)
return {
  modifyDamage: [
    { category: 'MISC_DAMAGE', value: 0.06 },  // Ability bonus
    { category: 'MISC_DAMAGE', value: 0.12 }   // Chain finisher bonus
  ]
};
```

**Right**:
```javascript
// Calculate SINGLE appropriate value
let damageBoost = 0;
if (isAbility) damageBoost = 0.06;
else if (isChainFinisher) damageBoost = 0.12;

// Return ONE modifier
return {
  modifyDamage: [
    { category: 'MISC_DAMAGE', value: damageBoost }
  ]
};
```

**Why**: Cleaner, more performant, clearer intent.

## Pitfall 3: Checking chainPosition for Non-LAs

**Wrong**:
```javascript
// DOT_TICK has chainPosition but is never a finisher
if (event.chainPosition === 3) { ... }
```

**Right**:
```javascript
// Check action type FIRST
if (event.action === 'LIGHT_ATTACK' && event.isChainFinisher) { ... }
```

**Why**: Non-breaking actions preserve `chainPosition` but never trigger chain-finisher bonuses.

## Pitfall 4: Breaking Chains Incorrectly

**Wrong** (adding to NON_BREAKING_ACTIONS carelessly):
```javascript
const NON_BREAKING_ACTIONS = ['DOT_TICK', 'HOT_TICK', 'ABILITY'];  // ❌
```

**Right**:
```javascript
const NON_BREAKING_ACTIONS = ['DOT_TICK', 'HOT_TICK'];  // ✓
```

**Why**: Abilities SHOULD break chains (player stopped light attacking). Only *passive* periodic effects should preserve chains.

=== LESSONS LEARNED ===

1. **State Persistence**: Combatant state can track per-combatant data across events (lightAttackChain object).

2. **Event Enrichment**: Adding computed properties to events (`isChainFinisher`, `chainPosition`) makes bunkers simpler.

3. **Weapon-Specific Behavior**: Configuration maps (`WEAPON_CHAIN_FINISHERS`) enable weapon-specific logic without hardcoding.

4. **Non-Breaking Actions**: Distinguish active player actions (break chains) from passive periodic effects (preserve chains).

5. **Conditional Modifiers**: Calculate single appropriate value instead of returning competing modifiers.

6. **Logging is Gold**: Console logs for chain state changes make debugging chain-dependent perks trivial.
