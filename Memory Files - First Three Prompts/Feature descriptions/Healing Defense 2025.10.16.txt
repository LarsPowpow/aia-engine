Key Learnings
1. Effect Targeting Architecture
Problem: Effects were being applied to the wrong combatant because the engine's grouping logic ignored targetId from bunkers.

Solution:

Lesson: Always preserve targetId from bunkers through the entire effect pipeline.

2. Instant vs. Persistent Effects
Problem: Instant heals (duration: 0) were being added to activeEffects array, polluting the UI.

Solution:

Lesson: Instant effects (duration: 0) should never appear in activeEffects - they happen immediately and have no ongoing state.

3. Value vs. ValueType Pattern
Problem: Healing percentages (0.025) vs. actual HP (263) caused confusion in the UI.

Solution:

Lesson: Use valueType to distinguish between raw values and percentages that need calculation.

4. Data Flow for Combat Log
Problem: Healing data wasn't reaching the Combat Analysis table.

Data Flow:

Bunker → Returns { applyEffects: [{ category: 'HEAL', value, valueType, targetId }] }
Engine → Collects heals in effectRequests, adds to eventAnalysis.healing[]
Engine → Calculates eventAnalysis.totalHealing (lines 161-174)
UI → Reads entry.totalHealing or calculates from entry.healing[] array
Lesson: Track where data is transformed at each layer and ensure it's preserved through the pipeline.

5. UI Filtering Best Practices
Problem: Old instant effects cluttering the Inspector display.

Solution:

Lesson: Filter display data to match user expectations - instant effects shouldn't show as "active" since they're already done.
