=== HEALING BREEZE II + HOT SYSTEM IMPLEMENTATION ===
Date: 2025-10-21
Status: ✅ COMPLETE
Complexity: High (Major engine infrastructure)

=== FEATURE DESCRIPTION ===

Perk: Healing Breeze II
Effect: When applying a healing effect to yourself, Heal yourself for 5.25% weapon damage for 6s.
Cooldown: 10s per target
Category: Weapon Perk (Heal over Time)

Simplified Design Decision:
- Initially considered 15% healing for others, 5.25% for self
- User requested simplification: Only self-heal at 5.25%
- Final: HoT always targets self (the healer) at 5.25% weapon damage per tick

=== TECHNICAL IMPLEMENTATION ===

## 1. HoT System Infrastructure (NEW)

This was the FIRST HoT (Heal over Time) implementation in the engine.

### Architecture Decision: Mirror DoT System

**Why**: DoT system already proven, tested, and understood by developers.

**Components Added**:

1. **HOT Effect Category**
   - Stored in activeEffects just like DOT
   - Anti-stack by effect ID (no stacking, no refresh)
   - Contains: healPercent, metadata (weaponType, attributes)

2. **HOT_TICK Event Type**
   - Generated by tick injection system (same as DOT_TICK)
   - Fires every 1.0s based on tickInterval
   - Carries: healPercent, metadata for dynamic calculation

3. **State Manager Integration**
   - Added HOT category handling (lines ~104-127)
   - Same pattern as DOT (anti-stack by ID)
   - Blocks duplicate HoTs with same ID

4. **Tick Injection**
   - Modified injectDOTTickEvents to handle HOT
   - Checks for HOT in activeEffects
   - Generates HOT_TICK when nextTickAt matches currentTime

5. **HOT_TICK Handler**
   - Recalculates weapon damage from stored metadata
   - Applies current healing modifiers (Sacred, Divine)
   - Dynamic healing (scales with buffs applied after HoT)

## 2. Two-Pass Effect Bunker Execution (NEW)

**Problem**: Healing Breeze needs to trigger when OTHER bunkers create HEAL effects.

**Solution**: Execute effect bunkers in TWO passes:
- Pass 1: Collect initial effects (Healing Defense creates HEAL)
- Pass 2: Reactive effects see Pass 1 results (Healing Breeze sees HEAL, creates HOT)

**Code Location**: engine.js, lines ~665-695

**Pattern for Reactive Bunkers**:
```javascript
function handler(context) {
  const { effectRequests } = context;
  
  // Skip Pass 1 (no effectRequests yet)
  if (!effectRequests) return null;
  
  // Check for triggering effects in Pass 1
  const hasTrigger = effectRequests.some(eff => ...);
  
  if (hasTrigger) {
    // Create reactive effect
    return { applyEffects: [...] };
  }
}
```

## 3. Healing Breeze II Bunker

**File**: `/src/simulation/bunkers/generated/perk_healing_breeze_ii.js`

**Trigger Logic**:
1. Check event.action !== 'HOT_TICK' (infinite loop prevention)
2. Check effectRequests exists (Pass 2 only)
3. Check for HEAL effects (exclude lifesteal and HoT)
4. Check per-target cooldown (10s)
5. Create HOT effect

**HOT Effect Structure**:
```javascript
{
  id: 'healing_breeze_ii_hot',
  category: 'HOT',
  sourceId: source.id,
  targetId: source.id,  // ALWAYS self
  value: 0.0525,        // For UI (5.25%)
  healPercent: 0.0525,  // For calculation
  duration: 6,
  tickInterval: 1,
  appliedAt: timestamp,
  nextTickAt: timestamp + 1,
  expiresAt: timestamp + 6,
  metadata: {
    sourceName: 'Healing Breeze II',
    healType: 'hot',
    weaponType: source.weaponType,      // CRITICAL
    attributes: { ...source.attributes } // CRITICAL
  }
}
```

**Critical Metadata**: 
- `weaponType` and `attributes` required for dynamic weapon damage calculation
- Without these, healing = 0 (no base damage to scale from)

## 4. HOT_TICK Handler

**File**: `/src/simulation/engine.js`, lines ~1016-1120

**Processing Steps**:

1. **Recalculate Weapon Damage**:
   ```javascript
   const weaponDamage = calculateWeaponDamage(
     event.metadata.weaponType,
     event.metadata.attributes
   );
   const baseHealing = weaponDamage * event.healPercent;
   ```

2. **Collect Healing Modifiers**:
   - From active effects (HEALING_EFFICIENCY, DIVINE_HEALING)
   - From modifier bunkers (Sacred II, Divine II)

3. **Calculate Final Healing**:
   ```javascript
   const totalMultiplier = 1 + healingEfficiency + divineHealing;
   const finalHealing = Math.round(baseHealing * totalMultiplier);
   ```
   
   **Important**: Additive multipliers (same as regular HEAL effects)

4. **Apply Healing**:
   ```javascript
   target.currentHp = Math.min(target.maxHp, target.currentHp + finalHealing);
   ```

5. **Return Event Analysis**:
   ```javascript
   {
     timestamp,
     action: 'HoT Tick (Healing Breeze II)',
     healing: finalHealing,  // As NUMBER
     snapshot: { ... }
   }
   ```

=== BUGS FIXED ===

## Bug 1: HoT Healing for 0

**Symptom**: HOT_TICK events show 0 healing.

**Root Cause**: Missing weaponType and attributes in HOT metadata.

**Fix**: Always include full metadata when creating HOT effect:
```javascript
metadata: {
  weaponType: source.weaponType,
  attributes: { ...source.attributes }
}
```

## Bug 2: Divine II Not Boosting HoT

**Symptom**: Sacred II boosted HoT (+6.5%), but Divine II didn't (+5.5%).

**Root Cause**: Incorrect formula (Divine added flat instead of multiplied).

**Wrong**:
```javascript
finalHealing = baseHealing * (1 + healingEfficiency) + divineHealing;
// 200 * 1.065 + 0.055 = 213.055 (Divine does almost nothing!)
```

**Right**:
```javascript
totalMultiplier = 1 + healingEfficiency + divineHealing;
finalHealing = baseHealing * totalMultiplier;
// 200 * (1 + 0.065 + 0.055) = 200 * 1.12 = 224 ✓
```

**Lesson**: Match formula to regular HEAL processing (additive multipliers).

## Bug 3: Blank Healing in Combat Analysis Table

**Symptom**: 
- Live Combat Log: "HOT Tick: 200 healing" ✓
- Combat Analysis table: Blank healing column ✗

**Root Cause**: 
1. Engine wraps `healing: 200` into `[200]`
2. totalHealing calculation expected objects with `.value` property
3. `h.value = undefined` for plain numbers
4. `totalHealing = 0`

**Fix**: Check `typeof h === 'number'` before accessing `.value`:
```javascript
eventAnalysis.totalHealing = eventAnalysis.healing.reduce((sum, h) => {
  if (typeof h === 'number') {
    return sum + h;  // NEW: Handle plain numbers
  }
  // Existing object logic...
  return sum + (h.value || 0);
}, 0);
```

**Code Locations**:
- Engine: `/src/simulation/engine.js`, lines ~202-217
- Table: `/src/components/CombatSimulatorPage.jsx`, lines ~56-86

## Bug 4: HOT Category Unknown

**Symptom**: Console warning "Unknown effect category: HOT, applying without special logic"

**Root Cause**: State manager didn't recognize HOT category.

**Fix**: Add HOT handling to stateManager.js (same pattern as DOT):
```javascript
if (effectData.category === 'HOT') {
  // Anti-stack by effect ID
  const existingHoT = target.activeEffects.find(e => 
    e.category === 'HOT' && e.id === effectData.id
  );
  
  if (existingHoT) {
    return;  // Block duplicate
  }
  
  // Add to activeEffects
  target.activeEffects.push(newHoT);
}
```

## Bug 5: Modal Showing "20000%" or "N/A"

**Symptom**: Modal displays wrong HoT value.

**Root Causes**:
- "20000%": `value: 200` (absolute) interpreted as percentage, × 100 = 20000%
- "N/A": No `value` property at all

**Fix**: Store `value` as percentage (matching healPercent):
```javascript
{
  value: 0.0525,      // 5.25% for UI
  healPercent: 0.0525 // 5.25% for calculation
}
```

=== LESSONS LEARNED ===

1. **Metadata is Critical**: Always store weaponType + attributes for dynamic calculations
2. **Match Existing Patterns**: HoT mirrors DoT = easier to understand and debug
3. **Formula Consistency**: Divine must match regular HEAL processing (additive multipliers)
4. **Type Handling**: Engine data flow uses mixed types (numbers AND objects) - handle both!
5. **Three-Layer Defense**: Handle edge cases at multiple levels (engine, table, fallback)
6. **Reactive Patterns Need Two Passes**: Can't see other bunker effects in single pass
